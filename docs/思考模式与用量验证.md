# 思考模式与 Token 用量验证

## 当前实现

模型接入使用 langchain-deepseek 1.1.1。专用适配器读取响应的 reasoning_content，
ThinkingChatDeepSeek 补齐请求回传：思考模式且绑定工具时，原始 AIMessage 的该字段
与 tool_calls 一同发送；缺失时在发送前报错，不编造思考内容。

solver 的跨轮历史保存的是已处理的最终客户答复，不是模型原始思考消息，因此把最近对话
整理成对话材料输入。本轮工具循环保留原始 AIMessage。审批仍是原有 interrupt/resume。
思考正文不展示给客户，也不写进 Token 报告；开启外部追踪时应另行考虑其采集范围。

## 默认配置与覆盖

| 角色 | 默认思考模式 | 说明 |
| --- | --- | --- |
| triage | 关闭 | 简单分类先控制耗时 |
| solver | 关闭 | 普通咨询节省用量，复杂多步流程可手动开启 low |
| reviewer | 关闭 | 保留审查节点，样例中开启思考未见额外收益 |
| judge | 关闭 | 评测打分独立配置 |
| general | 关闭 | 普通模型调用默认模式 |

本地 .env 可以填写以下内容，不需要改 Python 源码：

```dotenv
TRIAGE_THINKING=false
SOLVER_THINKING=false
REVIEWER_THINKING=false
JUDGE_THINKING=false
DEEPSEEK_REASONING_EFFORT=low
THINKING_MAX_TOKENS=8192
```

单节点强度可覆盖，例如 SOLVER_REASONING_EFFORT=high。支持 low/high/max。
如需演示复杂流程，可手动设置 SOLVER_THINKING=true，其他节点继续关闭；目前未自动按问题复杂度切换。
节点开关优先于 DEEPSEEK_THINKING 全局开关；未填写任何开关时使用上表默认值。
如需全局关闭，设置 DEEPSEEK_THINKING=false，并删除或关闭已有节点 true 开关。
关闭思考时保留温度配置，开启时不发送无效温度参数；思考请求的超时为 120 秒，
输出预算为 8192 Token，可调整。预算不足导致 JSON 截断仍会按结构化失败处理。

修改 .env 后重启 Streamlit 或 API 进程，使配置一致生效。

## 用量在哪里看

- 网页演示侧栏的“本次运行的 Token 用量”可展开查看最近一次区间。
- run_turn、resume_turn 与对应 API 响应顶层增加 usage 字段。
- totals 汇总该区间；by_stage 按角色和思考开关分组；calls 是逐次数字记录。
- 首次运行到审批暂停与员工批准后的恢复分别统计，不能把恢复区间误当作完整会话用量。
- 重启后 GET 会话状态不会自动恢复历史数字用量。本次统计是响应级诊断，不是持久化账单。
- eval.py 的图调用统计包含分流、工具处理、审查及重试/审批恢复，不包含外部 judge 打分调用，报告明确标注。

字段：input_tokens、output_tokens、total_tokens、reasoning_tokens、cache_read_tokens、latency_seconds。
推理 Token 是输出子项，不能再次加进总 Token；缓存读取也是输入子项。
示例：输入 10、输出 7、其中推理 3，则总量是 17，不是 20。

接口没有返回的字段记录为 null，不当作零。汇总缺字段时只累计已知部分，
结合 missing_usage_calls、reasoning_reported_calls、cache_reported_calls 判断覆盖程度。
calls 统计 LangChain 逻辑调用；SDK 内部重试产生的额外计费未必可观测，以服务商账单为准。
PRICES 为空时不估算金额；存在缓存命中却没有对应价格时也不输出虚假的精确费用。

## 本地测试证据

2026-11-01 完整离线测试共 56 项通过，其中思考与用量测试为 9 项，使用真实适配器加 httpx.MockTransport 验证：

- 分角色默认值和全局/节点覆盖、非法配置；
- 工具响应思考内容的读取、检查点序列化器往返及后续请求回传；
- 非工具调用助手消息的思考字段也保留回传；
- 缺失字段时发送前失败，关闭思考时不要求该字段；
- 思考与 JSON 模式同时使用，以及结构化包装后的用量回调；
- Token 数字、推理子项、缓存命中、不重复计数、缺失用量和失败调用。

默认思考配置全部关闭，复杂多步流程可手动开启 solver。
思考开关的业务质量、耗时和费用需要在目标场景中进行真实对照，不能由离线协议测试推断。
审批批准/拒绝、安全校验、政策检索等测试覆盖对应流程。
完整分类与数量见 [README 的测试与评测](../README.md#测试与评测)；30 条模型评测场景与离线测试分别统计。

## 可选真实接口检查

先在项目环境中安装 requirements.txt。
下面的命令会产生 API 费用，使用的仅是虚构订单 ORD-CHECK-001，不修改业务数据库。

```powershell
conda activate ecommerce-after-sales-agent
# 在项目根目录执行：
python check_model.py --role solver --compare-thinking
```

同一模型关闭/开启思考各三次调用，总共六次，检查普通回复、工具请求、工具结果返回。
数字报告写入 .cache/model-check-usage.json。工具选择使用 auto，不使用思考模式不支持的 required。
若失败则直接报告，不悄悄切换成关闭模式伪装成功。

这个小检查只能比较连接兼容与该样例的用量，不能证明真实业务质量。
业务对照需固定模型、同一问题集、政策版本与演示数据，分别运行开/关并比较正确率、
安全行为、平均耗时和 Token。完整 eval 会执行模拟业务操作，需在独立演示数据中安排。

官方协议：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。
