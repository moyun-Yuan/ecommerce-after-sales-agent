# 模型调用与结构化输出

## 各调用的输出契约

| 调用位置 | 所需结果 | 当前实现 |
| --- | --- | --- |
| graph.triage_node | route、reason | TriageDecision |
| graph.solver_node | AIMessage 工具调用或自然语言答复 | 普通模型绑定业务工具 |
| graph.reviewer_node | 政策依据、引用、敏感信息、通过标记和理由 | ReviewDecision |
| eval.judge_correctness | pass、reason | CorrectnessDecision |
| eval.judge_groundedness | grounded、reason | GroundednessDecision |
| approval、respond | 程序确定性结果 | 不增加模型调用 |

共享的是 create_chat_model 模型工厂。默认可使用同一个 DeepSeek 模型名、地址与密钥，
不需要部署第二套模型，也没有训练新的模型。Python 中的模型对象、绑定后的 Runnable、
远端模型服务是不同概念；绑定不同配置不等于部署不同服务。

## 调用过程

schemas.py 中使用 Pydantic 定义字段，禁止多余字段和隐式类型转换，字段没有默认值时必须提供。
llm.invoke_structured 调用 model.with_structured_output(schema, method="json_mode")，
并显式将输出格式说明与 schema 加入提示词。

JSON 模式负责约束 JSON 格式，本地 Pydantic 负责检查必填字段、枚举和类型。
这不是声称服务端通过严格 JSON Schema 解码保证了所有字段。校验成功时返回 Pydantic 对象；
校验失败则抛出 StructuredOutputError，由业务节点决定下一步。

输出模式只绑定到这个调用包装器，不修改基础模型。solver 继续使用 bind_tools，
不会因 triage 的 JSON 模式而被迫用 JSON 向客户回复。AgentState 仍是 TypedDict：
它描述工作流状态，和单次模型输出的 Pydantic 契约不是同一层。

## 校验与失败处理

- 分流、审查和评分分别配置任务指令与输出契约。
- route 枚举、工具名称、JSON 字段和政策来源编号保持稳定，不翻译程序协议值。
- 工作流和评测统一使用 invoke_structured。
- 分类缺字段、非法枚举、格式校验失败会转人工，不默认进入完整工具处理路线。
- 审查结果格式失败会计一次未通过，返回 solver 修正，达到原有上限后由 respond 转人工。
- approved="false" 是字符串，会被校验拒绝，不会出现 bool("false") 为 True 的错误放行。
- 审查类型正确但结论矛盾，例如 grounded=false、approved=true，也不会放行。
- 评测格式失败计为未通过，并保留格式错误原因；不能把它解释为单纯业务质量差。
- 网络和鉴权错误保持抛出，不被掩盖成普通格式失败。

## 验证与边界

完整离线测试通过以下命令运行：`python -m unittest discover -s tests -v`。
通过 httpx.MockTransport 验证真实 LangChain 请求参数：结构化请求携带 response_format=json_object，
后续普通调用和业务工具调用不携带该格式约束。该测试没有发出外部 HTTP 请求。

离线协议测试不替代真实接口验证；字段合法不代表分类或审查事实一定正确。
reviewer 在既无检索片段、答复又不含政策来源编号时直接通过；退款审批执行发生在 reviewer 之前。
结构化校验不能单独解决这两处设计边界。
